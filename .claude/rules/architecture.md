# Architecture and design review

- Use the approved requirements from the same story workspace. Trace design decisions and risks back to the requirements and acceptance criteria.
- Document high-level components, technology choices, data flow, trade-offs, deterministic output, `check`/`sync` behavior, failure handling, and safe Markdown updates in `architecture.md`.
- Run a structured design review. Record findings in `design-review.md` with severity, recommendation, and final agreed decision; clearly separate accepted, deferred, out-of-scope, and blocking findings. Document deferred items instead of implementing them silently.
- Present the design and review for human approval or requested changes before implementation planning begins.
